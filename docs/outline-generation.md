# 文档编排

> 状态：设计稿 v0.1
> 依赖：[architecture.md](architecture.md) §11、[unit-schema.md](unit-schema.md)
> 本文件定义文档骨架的生成算法、编号规则与手工修改的合并策略。

---

## 1. 目标

由知识点集合生成为一份可渲染的文档骨架（`outline.json`），并满足：

| 要求 | 判定 |
|---|---|
| 确定性 | 相同知识点集合与相同版本，生成结果逐字节一致 |
| 默认可用 | 无手工修改时结构合理，示例主体可直接阅读 |
| 可手工覆盖 | 人工调整结构后，重跑不丢失 |
| 追加稳定 | 新增讲次只影响末尾，既有编号不变 |

---

## 2. 输入

| 输入 | 来源 | 用途 |
|---|---|---|
| 知识点文件 | `.study/knowledge/units/*.md` | 内容与证据 |
| 前序讲次顺序表 | `study.config.yaml#lectures` | 讲次号与标题；缺失时由素材推断 |
| 既有 outline | `.study/outline.json` | 手工修改的载体 |
| 分区规则 | §7 | 复习课、附录、未归类内容 |

### 2.1 知识点的讲次归属

知识点跨讲共享，因此其归属不可由文件名推断，按以下顺序判定：

1. `evidence` 中出现次数最多的 `src` 对应的讲次
2. 若并列，取 `loc.slide`（或 `loc.page`）最小者所在讲次
3. 若仍并列，按 `src` 文件名排序取第一个

判定结果写入 `outline.json` 的 `_meta.unit_lecture`，便于人工核对。属于附录类（无任何讲次证据、或 `type: summary` 且证据跨多讲）的知识点进入 §7 的附录分区。

### 2.2 讲次内排序键

```
sort_key(unit) = (min_slide(unit), min_block_index(unit), id)
```

`min_slide` 取该知识点全部证据中幻灯片序号的最小值；无幻灯片证据（如仅有手记）时取所属讲次的最大幻灯片序号加一，使其落在该讲末尾；`min_block_index` 为同一幻灯片内的块序号，用于同一页上多个知识点的先后。

排序键完全由数据决定，不含模型判断。

## 3. 自动分节

一讲通常包含数十张幻灯片。平铺为数十节不可读，因此聚合为 2~5 节。

分节有两条路径，**编号优先**：

### 3.0 按素材自带编号分节（首选）

若该讲的知识点标题普遍带编号（如 `6.1`、`6.2.2`），则素材本身已经映射了层级，直接读取，不做猜测：

1. 计算每个标题的层级：`6.1` → 2，`6.2.2` → 3
2. 取该讲内**最浅层级**作为节边界（通常为 2）
3. 每个边界到下一个边界之间归为一节，节标题取该节第一个同层级标题
4. 首个边界之前的内容（封面、序言）并入第一节
5. 标题中的编号在渲染时剥离，避免「6.2.1 6.1 示例结构的定义」这类重复

约束：`第6章 示例专题` 这类**章节级**标题不参与最浅层级判定——它描述的是整讲，不是某一节。

单级编号（`2. 示例条目`）同样不算结构信号：它在实践中是节内的列表项，若当作边界会把一讲切碎。只有含小数点的编号（`x.y`）参与层级计算。

### 3.0.1 无编号课件的知识点切分

若该讲的知识点标题里带编号的不足 2 个，分节无从读起，改为**按标题连续段聚类**：

- 连续若干张幻灯片共享同一标题 → 一个知识点
- 标题变化且当前知识点已有 ≥2 张幻灯片 → 另起一个
- 只有 1 张幻灯片的段落并入上一个知识点（孤零零的单页知识点几乎都是大字号标签）

这决定了「一份没有任何编号的课件也能析出几十个知识点，而不是一个」。

### 3.1 边界候选（无编号时的回退）

以下规则仅在编号缺失或覆盖率不足一半时启用。



按排序顺序遍历知识点，在以下位置产生候选边界：

| 来源 | 权重 |
|---|---|
| 所属 IR 块为 `title` 且 `level <= 2` | 高 |
| 所属块为 `title` 且 `level >= 3` | 中 |
| `type` 由 `concept` 变为 `property` / `algorithm` 等 | 低 |
| 与前一知识点的 `depends_on` 无交集且 `see_also` 无交集 | 低 |

### 3.2 选择

1. 每讲目标节数为 `clamp(round(sqrt(n)), 2, 5)`，`n` 为该讲知识点数。知识点少于 3 个时不分节。
2. 以高权重候选为优先，贪心选取使各节知识点数尽量均衡的边界。
3. 中、低权重候选仅在高权重候选不足以达到目标节数时启用。
4. 合并知识点数少于 2 的节（首节与末节除外）。
5. 无任何候选边界时，按序号等分为目标节数。

### 3.3 节标题

1. 边界处若有 `title` 块，取该块文本
2. 否则取该节第一个知识点的 `title`，若超过 16 字则截断至语义完整处
3. 仍不可得时命名为「第 n 讲（续）」形式

节标题不做模型生成，保证确定性。

## 4. 编号

### 4.1 规则

```
讲次     n            （n 为正整数，附录为 A、B……）
节       n.m
知识点   n.m.k
图/表    n.m.k-1, n.m.k-2
公式     (n.m.k)
```

编号在渲染时计算，不写入任何数据文件。渲染器负责维护计数器并在目录、页眉、交叉引用处保持一致。

### 4.2 编号稳定性

追加新讲次时，既有讲次的 `n` 不变，因此其下的节号与知识点号全部不变。这是选择按课件顺序编排的直接收益。

删除或重排讲次会改变后续编号，此时渲染器须检查：

- 交叉引用是否仍可解析（`dangling_refs`）
- 附录编号是否与正文冲突

### 4.3 交叉引用的渲染

| 场景 | 渲染 |
|---|---|
| 引用同节内的知识点 | `上文` 或 `§n.m.k`（按模板配置，短文档用前者） |
| 引用其他节 | `§n.m` |
| 引用后续讲次 | `详见§n.m`（前向引用须显式标注） |
| 引用附录 | `附录 A` |

前向引用不得展开内容。若渲染时检测到前向引用超过 3 处集中于同一知识点，报告为 `minor` finding，提示该知识点可能需要前置说明。

## 5. outline.json 结构

```json
{
  "schema_version": 1,
  "parts": [
    {"kind": "front_matter", "title": "前言"},
    {
      "kind": "lecture", "no": 6, "title": "示例专题",
      "sections": [
        {"title": "基本概念", "units": ["binary-tree-def", "binary-tree-terms"]},
        {"title": "性质", "units": ["binary-tree-layer-max", "full-binary-tree-leaves"]}
      ]
    },
    {"kind": "review_lecture", "no": 7, "title": "复习课",
     "sections": [{"title": "全章梳理", "units": ["ch6-summary"]}]},
    {"kind": "appendix", "label": "A", "title": "公式速查",
     "sections": [{"title": "树与示例结构", "units": ["appx-tree-formulas"]}]}
  ],
  "_meta": {
    "generated_at": "2026-01-01T00:00:00Z",
    "pipeline_version": "0.1.0",
    "auto_hash": "sha256:...",
    "unit_lecture": {"binary-tree-def": 6, "huffman-construct": 6},
    "orphans": [],
    "unplaced": []
  }
}
```

| 字段 | 说明 |
|---|---|
| `kind` | `front_matter` / `lecture` / `review_lecture` / `appendix` / `unplaced` |
| `auto_hash` | 本次自动生成结果的哈希，用于三方合并（§6） |
| `orphans` | 存在于既有 outline 但已不存在的知识点 id，仅作提示，不阻塞 |
| `unplaced` | 存在于知识点集合但未能归入任何节的知识点 id，须人工处理 |

## 6. 手工修改与合并

### 6.1 三方合并

重新生成时以三方合并处理，避免覆盖人工调整：

| 版本 | 含义 |
|---|---|
| A | 上次自动生成的结果（由 `auto_hash` 校验完整性） |
| B | 当前文件（含人工修改） |
| C | 本次自动生成的结果 |

规则：

1. `B` 与 `A` 相同的位置视为未修改，采用 `C`。
2. `B` 与 `A` 不同的位置视为人工修改，保留 `B`。
3. 知识点在 `C` 中新增且未在 `B` 中出现，插入到其自动位置；若该位置已被人工移动过，插入至同一 `parts` 项末尾。
4. 知识点在 `B` 中存在但 `C` 中已删除，移入 `_meta.orphans`，同时从 `parts` 中移除，并在报告中列为 `blocker`。
5. `A` 校验失败（人工改动了 `auto_hash` 覆盖的自动内容）时，不合并，要求人工确认后以 `C` 为基础重建。

人工调整的位置记入 `moved_from`，用于区分「自动放置」与「人工放置」：

```json
"moved_from": {"binary-tree-layer-max": {"lecture": 6, "section": 2}}
```

### 6.2 手工操作的允许范围

| 操作 | 允许 |
|---|---|
| 移动知识点至其他节或讲次 | 是 |
| 重命名节标题 | 是 |
| 新增节、空节 | 是（空节在渲染时保留，作为人工占位） |
| 新增 `front_matter` / `appendix` 内容 | 是（文本型 part，`units` 可为空） |
| 修改知识点内容 | 否，应在 `units/` 中修改 |
| 修改 `_meta` | 否，`_meta` 由程序维护 |

---

## 7. 分区规则

| 内容 | 分区 | 判据 |
|---|---|---|
| 复习课、习题课 | `review_lecture` | 讲次标题匹配配置中的关键词，或该讲内新知识点占比低于阈值且证据多为跨讲汇总 |
| 跨讲对照表、公式汇总、术语表 | `appendix` | 证据跨 3 个以上讲次，且 `type: summary` 或人工指定 |
| 无法归属的知识点 | `unplaced` | 归属判定失败 |

`unplaced` 非空时渲染仍可进行，但门禁 `coverage` 报 `major`，并在 `review/findings.md` 中列出待归类清单。

---

## 8. 校验

| 检查 | 层 | 严重度 |
|---|---|---|
| 所有知识点均出现在 `parts` 中，或在 `unplaced` | L1 | major |
| 同一知识点不得出现两次 | L1 | blocker |
| 节内 `units` 均存在 | L1 | blocker |
| 编号与渲染结果一致（抽样反查） | L1 | blocker |
| 前向引用密度过高 | L1 | minor |
| `orphans` 非空 | L1 | blocker |

---

## 9. 稳定性验收

编排部分的实现须通过以下用例：

1. 相同输入连续生成两次，`outline.json` 除 `_meta.generated_at` 外逐字节一致。
2. 在已有 5 讲的课程后追加第 6 讲，前 5 讲的 `parts` 项与全部编号不变。
3. 手工将某知识点从第 2 节移至第 3 节，重新生成后位置保持。
4. 手工改坏 `auto_hash` 对应区域后重新生成，程序拒绝合并并要求确认。
5. 删除某知识点后重新生成，该 id 出现在 `_meta.orphans` 且报告为 `blocker`。
