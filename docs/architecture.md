# 架构

> 状态：设计稿 v0.1
> 适用范围：本仓库的全部实现
> 阅读前提：熟悉课件、讲义类文档的基本形态即可，无需了解具体课程的学科内容

本文件定义 study-harness 的分层结构、数据契约与质量约束。实现与测试均以本文件为准；本文件与实现不一致时，视为缺陷。

---

## 1. 目标

将一门课程的多种学习资料（演示文稿、PDF、Word 文档、纯文本、课堂录音、学生手记）转换为**可独立阅读的连续文档**，并满足以下四项要求：

| 要求 | 判定方式 |
|---|---|
| 可复现 | 相同输入与相同管道版本产生逐字节相同的产物 |
| 可增量 | 新增讲次或修改单份素材，仅影响相关知识点 |
| 可溯源 | 每条陈述都能追溯到具体证据位置（内部保留，是否呈现可配置） |
| 厂商中立 | 核心能力由确定性程序实现，不依赖特定模型或客户端 |

---

## 2. 设计原则

以下四项为全部设计决定的依据。出现取舍争议时，以本节为判定标准。

| 编号 | 原则 | 含义 |
|---|---|---|
| P1 | 中间表示优先 | 所有素材先转换为带定位符的结构化块，上层能力一律建立在中间表示之上。禁止将素材直接拼接为长文本后交由模型处理。 |
| P2 | 确定性层与语义层分离 | 程序可完成的工作不调用模型；调用模型之处，其输出必须落盘为文件，可缓存、可复核、可人工替换。 |
| P3 | 内容是缓存，文档是投影 | 知识点具有稳定身份并按内容哈希缓存；成书是纯装配动作，重复执行无额外成本。 |
| P4 | 厂商中立 | 核心能力由命令行程序提供。任意代理（Claude Code、Codex、Cursor 或人工）均作为薄适配层存在，模型产物以缺口文件形式交换。 |

---

## 3. 非目标

- **不处理视频画面**。v1 不抽取视频帧。`ingest/media.py` 保留 `frames` 参数，后续扩展不构成架构变更。
- **不生成无差别的前置知识**。无法得知示例主体既有知识范围，因此仅在示例主体明确提出缺口时生成补丁（见 §15）。
- **不提供在线服务**。无服务端、无账号体系，默认全本地离线运行。
- **不在仓库内附带课程内容**。框架与内容严格分离（见 §18）。

---

## 4. 处理流程

```
① ingest   确定性   各格式 → IR 块（图片仅执行 L0/L1，L2 只登记缺口）
       ↓  .study/sources/*.jsonl + assets/
② probe    确定性   产出能力清单，据此确定音频对齐档位
       ↓  .study/probe.json
③ align    半确定性 录音时间窗映射至幻灯片序号（仅 A/B 档）
       ↓  .study/aligned/s*/align.json
④ 知识化   语义层   抽取知识点（含 L2 读图缺口）、跨模态合并、生成判重候选
       ↓  .study/knowledge/units/u-*.md
⑤ 编排     确定性   依课件顺序生成 outline，计算编号
       ↓  .study/outline.json
⑥ 渲染     确定性   按 scope / profile / lang 渲染，叠加补丁，剥离或保留来源指称
       ↓  .study/out/
⑦ 门禁     确定性   结构检查（硬阻断）：来源指称策略、悬空引用、未定义符号、数值复算
       ↓  exit code + 报告
⑧ 审查     语义层   证据支撑审查与独立对抗审查，产出 findings（不自动修改内容）
       ↓  .study/review/findings.{jsonl,md}
```

各阶段产物一律落盘，可中途检查与人工修改。支持从任意阶段续跑（`study build --from align`）。

## 5. 工作区布局

仓库本身不包含课程数据。使用者在任意目录创建工作区：

```
<workspace>/
├── study.config.yaml          # 课程名称、语言、模板、来源指称策略、素材路径
├── inputs/                    # 原始素材，只读，不被修改
│   ├── lecture-06.pptx
│   ├── rec-06.m4a
│   └── my-notes.yaml          # 学生手记
└── .study/
    ├── state.json             # 阶段状态、输入内容哈希、管道版本
    ├── probe.json
    ├── sources/               # 规范化 IR
    │   ├── pptx-lecture-06.jsonl
    │   ├── media-rec-06.jsonl
    │   └── notes-my-notes.jsonl
    ├── assets/                # 图片、公式渲染结果、抽取的帧
    ├── aligned/
    │   └── s06.align.json
    ├── gaps/                  # 待填充的模型任务
    │   ├── g0042.json
    │   └── answers/
    ├── knowledge/
    │   ├── units/u-*.md       # 知识点本体，跨讲共享
    │   └── graph.json         # 依赖图与候选合并清单
    ├── outline.json           # 文档骨架，可手工修改
    ├── patches/               # 学生手记与按需补丁，与知识点本体隔离
    │   ├── notes.yaml
    │   └── remedial/
    ├── review/                # 审查产物与人工复核队列
    └── out/                   # 渲染产物
```

`state.json` 以「输入文件 sha256 + 管道版本」作为阶段缓存键。任一输入或程序版本变化时，仅重跑受影响阶段。

## 6. 中间表示

每个块占一行 JSONL。`loc` 字段为该块的坐标，是溯源、对齐与去重的基础。

```jsonl
{"id":"s03-012","src":"lecture-03.pptx","type":"bullet","text":"每本示例条目最多同时被 3 位示例主体示例操作","loc":{"slide":12,"shape":4}}
{"id":"s06-013","src":"lecture-06.pptx","type":"image","asset":"assets/s06-013.png","ocr_text":null,"semantics":null,"loc":{"slide":13}}
{"id":"s06-013a","src":"lecture-06.pptx","type":"formula","latex":"T(n)=2T(n/2)+O(n)","loc":{"slide":13}}
{"id":"rec06-0088","src":"rec-06.m4a","type":"speech","text":"第 i 层最多 2 的 i 减 1 次方","loc":{"t":[812.5,845.2]}}
{"id":"nt-0007","src":"my-notes.yaml","type":"note","text":"i 从 1 开始计，常考","kind":"emphasis","loc":{"slide":12}}
```

### 6.1 块类型

| type | 必需字段 | 说明 |
|---|---|---|
| `title` | `text`, `level` | 标题层级，用于自动分节 |
| `bullet` | `text` | 正文条目 |
| `formula` | `latex` | 由 OMML/MathML 线性化得到，要求可逆 |
| `table` | `rows` | 二维数组 |
| `image` | `asset`, `ocr_text`, `semantics` | 见 §7 |
| `speech` | `text`, `loc.t` | 录音转写，带时间区间 |
| `note` | `text`, `kind` | 学生手记，见 §8 |
| `code` | `text`, `lang` | 代码块 |

### 6.2 定位符

| 素材类型 | `loc` 形态 |
|---|---|
| 演示文稿 | `{"slide":12,"shape":4}` |
| PDF | `{"page":37,"bbox":[x,y,w,h]}` |
| Word | `{"para":214}` |
| 录音 | `{"t":[812.5,845.2]}`，具备词级时间戳时附带 `words` |
| 学生手记 | 以上任一，或省略（全局笔记） |

### 6.3 来源指称策略

来源指称（正文中提及素材出处，如「见课件第 12 页」「如录音所述」）由配置项控制，默认关闭：

```yaml
render:
  source_references: none     # none | footnote | inline
```

| 取值 | 行为 | 门禁处理 |
|---|---|---|
| `none`（默认） | 正文与页脚均不含任何来源指称。定位符仅存于 `knowledge/`，供维护者与审查使用。 | `source_reference_policy` 拒绝正文出现指称词 |
| `footnote` | 正文不含指称词；定位以中性标记（如 `[6-12]`）附于脚注，并在书末给出标记说明。 | 仅允许脚注区出现中性标记，正文出现指称词即失败 |
| `inline` | 允许在括号中标注出处。 | 不做限制 |

禁止词表（`none` 与 `footnote` 模式下生效）：课件、PPT、幻灯片、该页、老师、课上、课堂、录音、视频、原书、讲义原文。

无论取值为何，带定位符的核对版本（`render --audit-locators`）只写入 `.study/review/`，不进入 `out/`。

## 7. 图片处理

图片按「信息是否已被更廉价的处理手段捕获」逐级降级处理。

| 级别 | 手段 | 触发条件 | 成本 |
|---|---|---|---|
| L0 | 文本对象（OMML、表格、SmartArt 文字、组合形状） | 默认路径 | 无 |
| L1 | 区域 OCR（图片内文字） | 图片区域内存在文字 | 低，可离线 |
| L2 | 多模态读图 | L1 之后该块语义仍不完整 | 高且不确定，必须缓存 |

L2 的触发条件不是「图片复杂」，而是 **L1 之后的信息缺口**。因此 L2 请求必须表述为具体问题，而非「描述这张图」：

```json
{
  "id": "g0042",
  "kind": "image_semantics",
  "asset": "assets/s06-013.png",
  "question": "图中节点之间的有向边集合是什么？请以 [(源,目标), ...] 形式回答。",
  "context": {
    "unit_hint": "示例操作上限",
    "ocr_text": ["A", "B", "C", "D", "E"],
    "missing": "边的集合"
  }
}
```

此设计将 L2 由开放描述转为受限填空，使结果可验证、可人工代填、可缓存。

公式在演示文稿与 PDF 中绝大多数为文本对象而非位图。此类内容必须走 L0；交由多模态模型识别的准确率显著更低。

### 7.1 图形的三种来源

图形并非只有"照搬"一种来源。入库的图分为三类，来源必须记录在图的元数据中，并在渲染时区别对待：

| 来源 | 含义 | 存储 | 典型格式 |
|---|---|---|---|
| `extracted` | 从素材原样导出 | 内容哈希命名，二进制 | png / emf / jpg |
| `redrawn` | 与素材内容相同，但重画为可编辑的矢量 | 结构化文本 | mermaid / dot / svg / tikz |
| `synthesized` | 素材中没有，为讲解而新增 | 结构化文本 | mermaid / dot / svg / tikz |

约束：

- **重画与新增一律使用文本矢量格式**。位图无法 diff、无法审查、无法修正文字；由模型产出的图是一个"关于素材的断言"，必须可被人核对。
- `redrawn` 与 `synthesized` 必须携带 `evidence`（重画时指向原图所在位置，新增时指向其所解释的知识点）。
- `synthesized` 在复核前标记 `reviewed: false`，渲染正常但门禁提示。
- Mermaid 在国内主流代码托管平台可原生渲染，因此 `redrawn` 首选 mermaid，其次 svg（可直接嵌入）。

图形的生成请求以 `figure_request` 缺口形式发出，答案写着图规格文本而非位图，见 §16。

## 8. 学生手记

手记既是补充语料，也是锚点与缺口信号，二者均无法由其他途径获得。

```yaml
# inputs/my-notes.yaml
- at: {slide: 12}
  text: i 从 1 开始计，常考
  kind: emphasis          # 兼作对齐锚点

- at: {t: [812.5, 860]}
  text: 为什么是 2^(i-1)，没听懂
  kind: question          # 兼作对齐锚点

- at: {unit: book-def}
  text: 与高中所学的定义不一致
  kind: question

- text: 期中考试覆盖至第 6 章
  kind: global
```

| kind | 作用 |
|---|---|
| `emphasis` | 进入 `review` 视图的重点清单 |
| `question` | 标记难点；`learn` 视图在此处增加详解，并可生成按需补丁 |
| `correction` | 渲染时覆盖素材原文，适用于口头讲解与文稿不一致的情形 |
| `global` | 全局约束，如考试范围 |

手记不写入 `knowledge/units/`，仅存于 `patches/`，渲染时叠加。理由见 §10.1。

## 9. 音频对齐

工具面向第三方使用，不得预设使用者拥有录音或录音含有锚点。ingest 之后先执行 probe：

```json
{
  "audio":  {"present": true, "duration": 5412, "has_word_ts": true},
  "slides": {"count": 48, "speaker_notes": 31, "notes_with_timecodes": 0},
  "anchors":{"user_provided": 2, "detected_page_turns": 3}
}
```

代理读取 probe 结果后向用户确认，据此判定档位：

| 档位 | 条件 | 对齐方法 | 人工确认 |
|---|---|---|---|
| A | 存在手记锚点、备注页时间码，或检测到翻页 | 直接锚定，区间内插值 | 无 |
| B | 无锚点但录音可用 | 词面重叠（中文按字符 n-gram，不依赖分词）配合单调动态规划约束（幻灯片序号非递减） | 仅低置信度段落，每讲约 3~8 处 |
| C | 无录音 | 跳过对齐，仅使用幻灯片与备注页 | 无 |

C 档必须能完整跑通全部流程，以保证无录音用户可用。v0.1 仅实现 C 档。

## 10. 知识点

知识点是文档的基本单元，也是缓存的单位。

```markdown
---
id: loan-limit
title: 单本示例条目的并发示例操作上限
type: 性质
evidence:
  - {src: lecture-06.pptx, loc: {slide: 12}}
  - {src: rec-06.m4a,     loc: {t: [812.5, 845.2]}}
  - {src: my-notes.yaml,  loc: {slide: 12}, kind: emphasis}
depends_on: [book-def]
see_also: [overdue-freeze]
emphasis: true
origin: source
revision: 3
suspects: [overdue-freeze]
---

单本示例条目最多同时被 $k$ 位示例主体示例操作（$k$ 由馆藏策略设定，默认 3）。

**依据**：第 $i$ 层每个元素最多有两个子元素……

**用途**：已知层数求最坏情况下的元素总数 $2^h-1$……
```

### 10.1 溯源的两个维度

| 维度 | 取值 | 面向 | 是否进入正文 |
|---|---|---|---|
| `origin` | `source`（原文明确陈述）/ `derived`（可由原文推出）/ `synthesized`（补充内容） | 示例主体与门禁 | 是（`synthesized` 可选标注） |
| `evidence` | `[{src, loc}]` | 仅维护者与审查 | 否，按 §6.3 策略输出 |

补充内容与个人手记一律不写入知识点本体，而存于 `patches/`，原因有二：其一，更新课程素材时不会与个人笔记产生冲突；其二，个人数据不得进入公开仓库。

### 10.2 符号与术语

正文中出现的每个符号必须在本文件更早处有定义。术语由 `glossary.yaml` 统一管理，记录术语 ID 及中英文对照。多语言在渲染层处理，不在 ingest 阶段翻译，以免污染证据并降低词面对齐质量。

## 11. 文档编排

文档结构默认按课件（讲次）顺序组织，不按知识依赖拓扑排序。

依据：

1. 新讲次追加于末尾，既有章节编号不位移，版本差异集中且易审阅。
2. 课件顺序为客观数据，可由程序直接计算，结果可复现、可比较。
3. 与示例主体按周次学习的进度一致。
4. 授课顺序本身已隐含知识依赖。

### 11.1 结构规则

```
文档 = [前言] + Σ 讲次 → 节 → 知识点 + [复习课章] + [附录]
知识点顺序 = 该讲次幻灯片顺序
节边界 = 自动分组（标题层级与内容跨度），outline.json 可手工修改
```

**规则一：讲次内自动分节。** 一讲的数十张幻灯片不分列为数十节，按标题层级与内容跨度聚合为 2~5 节。

**规则二：前向依赖使用引用，不搬运内容。** 第 2 讲使用第 9 讲才讲授的概念时，书写为「（详见 §9.2）」并附一句最小必要说明。搬运内容会破坏增量更新的可维护性。

**规则三：以下三类内容不置于讲次内。**
- 复习课与习题课：独立成章，其内容本不遵循新知识点顺序。
- 跨讲对照表、公式速查、术语表：置于书末附录，避免在多讲重复出现。
- 学生补丁：数据上独立，渲染时叠加至对应位置。

### 11.2 编号

- 知识点身份为 `id`（slug），不随结构变化。
- 章、节、图、表编号在渲染时依 outline 顺序计算，不写入数据。
- 交叉引用在数据中写作 `[[unit-id]]`，渲染为 `§3.2`。

因此插入、删除与重排仅影响渲染结果，不影响内容。

### 11.3 outline.json

`outline.json` 为一级产物，可手工修改，默认生成结果应可直接使用。

```json
{
  "parts": [
    {"kind": "front_matter", "title": "前言"},
    {"kind": "lecture", "no": 6, "title": "示例专题",
     "sections": [
       {"title": "基本概念", "units": ["book-def", "binary-tree-terms"]},
       {"title": "性质", "units": ["loan-limit", "overdue-freeze"]}
     ]},
    {"kind": "review_lecture", "title": "复习课"},
    {"kind": "appendix", "title": "公式速查"}
  ],
  "moved_from": {"loan-limit": "lecture-6/auto-2"}
}
```

## 12. 渲染接口

```
render(units, scope, profile, lang, outline, patches)
```

| 参数 | 取值 | 说明 |
|---|---|---|
| `scope` | `unit` / `lecture` / `lectures` / `chapter` / `semester` | 输出范围，与成书结构解耦 |
| `profile` | `learn` / `review` | 同一批知识点的两种呈现 |
| `lang` | `zh` / `en` / `bilingual` | 在渲染层处理，IR 保留原文 |
| `source_references` | `none` / `footnote` / `inline` | 见 §6.3 |

- **learn**：依 outline 顺序；先陈述动机与问题；推导完整；每个概念配可计算的例子；`question` 处增加详解。
- **review**：结论与判据前置；提供对照表与易错点；`emphasis` 项汇总为重点清单；附公式速查。

模板以数据形式存于 `templates/`，不得硬映射于程序。

## 13. 质量门禁

确定性检查，不通过则返回非零退出码。

| 门禁 | 检查内容 |
|---|---|
| `source_reference_policy` | 正文来源指称符合 §6.3 配置 |
| `dangling_refs` | `[[id]]` 指向不存在的知识点 |
| `undefined_symbols` | 正文符号在本书更早处无定义 |
| `undefined_terms` | 术语不在 glossary 中且未就地定义 |
| `coverage` | 每张幻灯片或被至少一个知识点引用，或在 outline 中标记为「略」 |
| `formula_roundtrip` | LaTeX 与 OMML 双向转换可逆（抽样） |
| `numeric_check` | 例题、边界值、复杂度断言以符号计算重算，结果须一致 |
| `patches_stale` | 补丁指向的知识点已删除或已修改 |
| `workspace_clean` | `inputs/` 与 `.study/` 未被纳入仓库 |

不设置 `self_sufficiency` 类门禁（要求知识点各段齐全）。由于无法获知示例主体既有知识范围，强制补全等价于生成无依据的前置知识。相关需求由 §15 的按需补丁承担，并辅以上述符号与术语检查。

## 14. 语义审查

审查分四层，性质不同，须分别执行。

| 层 | 执行者 | 能否阻断 | 产物 |
|---|---|---|---|
| L1 结构检查 | 程序 | 能 | 直接失败（见 §13） |
| L2 证据支撑审查 | 模型（经 §16 缺口协议） | 否，仅标记 | `review/findings.jsonl` |
| L3 独立对抗审查 | 另一模型或无写作上下文的新会话 | 否 | `review/findings.jsonl` |
| 人工复核 | 人 | 能（决定是否应用） | `review/findings.md` |

**约束：审查产物不得自动修改知识点。** 审查仅生成 findings 与建议补丁，由人工执行 `study review apply` 后生效，并在 `state.json` 中记录修改来源。否则产物不可复现，且无法区分陈述的来源。

### 14.1 错误分类

| 类型 | 典型形态 | 检测手段 |
|---|---|---|
| 事实错 | 陈述与证据不符；图中元素为臆造；引用了不存在的术语 | L2 逐条断言做蕴含判断 |
| 推导错 | 公式抄写错误、算例错误、遗漏边界条件 | `formula_roundtrip` 与 `numeric_check`，须实际重算 |
| 表述错 | 符号含义前后不一致、同一概念使用两套术语、前后陈述矛盾 | `undefined_symbols`、`undefined_terms` 与 L3 跨知识点矛盾扫描 |

### 14.2 L2 证据支撑审查

将每个知识点的正文拆分为可判定的断言，逐条判定：

```json
{"unit": "loan-limit", "claim_idx": 2,
 "text": "超期未还的示例条目会被自动冻结示例操作资格",
 "verdict": "supported", "evidence": [{"src":"lecture-06.pptx","loc":{"slide":12}}]}
```

| verdict | 含义 | 处理 |
|---|---|---|
| `supported` | 可由该知识点的证据直接推出 | 无需处理 |
| `derived` | 不能直接推出，但可由本书已有内容合理推得 | 标记 `origin: derived` |
| `unsupported` | 两者皆不成立 | 删除，或标记 `origin: synthesized` 并在正文中说明其为补充内容 |

`unsupported` 占比为本项目的核心质量指标：占比过高说明生成内容缺乏依据；占比低而 `derived` 高，说明补充内容超出素材范围，应复核。

### 14.3 L3 独立对抗审查

审查者不得为作者。同一模型携带写作上下文审查自身产物，几乎必然通过。

- 使用不同模型，或至少使用全新上下文。
- 仅提供成品正文与该知识点的证据，不提供写作过程。
- 任务为单一指令：「找出这段教学内容中会导致学习者形成错误理解的地方」。
- 固定检查项：① 与本书其他知识点是否矛盾；② 是否遗漏关键步骤；③ 算例是否可实际算出。

成本控制：仅审查 `formula`、`numeric`、`origin: synthesized` 类型及被标记为 `question` 的知识点，其余按比例抽样。

### 14.4 人工复核队列

L2 与 L3 的 findings 汇总至 `review/findings.md`，按严重度排序：

```
[blocker] u-loan-limit  断言 3 无证据支撑，且与 u-overdue-freeze 矛盾
          建议：删除，或改为 synthesized 并标注
[minor]   u-huffman-construct      「左小右大」与「左大右小」两种表述并存
```

`review/` 是工作区中唯一允许出现定位符的目录，其中文件不属于交付文档。

## 15. 按需补丁

示例主体明确提出缺口时生成，用于替代无差别的前置知识补充：

```bash
study explain loan-limit      # 标记某知识点有疑问
study explain --prereq 递归               # 标记前置概念有疑问
```

产物写入 `patches/remedial/<slug>.md`，含 `origin: synthesized` 与 `requested_by: student`，渲染时插入至需要它的知识点之前——正文中以「补充说明（非课程原有内容）」的引用块标出，示例主体始终能分清哪些是素材原有、哪些是补的。

流程：

```bash
study explain <unit> [--focus "只讲这个疑点"] [--prereq]   # 写缺口
study gaps fill remedial-<unit> --file answer.json         # 填答案
study explain --apply                                      # 转成补丁
study render                                               # 叠加到正文
study explain --remove <unit>                              # 删除，原文自动恢复
```

- 不写入 `knowledge/units/`：删除无残留，课程更新时不产生冲突。
- 明确标注为补充内容：示例主体可区分素材原有内容与补充内容。
- 仅补充被要求的部分：成本可控，结果可验证。

## 16. 模型接口

命令行程序不直接调用模型。凡需语义处理之处，输出缺口文件，由任意代理或人工填充：

```
.study/gaps/g0042.json         # 问题，含上下文与期望格式
.study/gaps/answers/g0042.json # 答案，来源不限
```

```json
{
  "id": "g0042",
  "edges": [["A","B"],["A","C"],["B","D"],["C","E"]],
  "by": "claude-code/opus",
  "confidence": "high"
}
```

缺口类型与来源：

| kind | 触发 | 答案用途 |
|---|---|---|
| `image_semantics` | 图片无 `semantics` | 写入 IR 的 `semantics`，进入正文「图示说明」 |
| `page_text` | 页面无文字层（扫描/纯图页） | 转写页面文字 |
| `figure_request` | 需要重画或新增的图 | 图规格文本（矢量），见 §7.1 |
| `claim_entailment` | L2 审查 | 逐条断言的 verdict |
| `remedial` | 示例主体声明缺口 | 前置讲解补丁 |

答案校验：`gaps fill` 按缺口声明的 `answer_format` 校验，出现未声明字段即拒绝写入——宽松接受会让「模型自由发挥」重新进入管道。

由此获得四项性质：无模型时仍可完成流程（缺口留空并标记未填）、可更换任意模型、可人工代填、结果可缓存与复核。`SKILL.md`、`AGENTS.md`、`.cursor/rules` 均为同一命令行的适配层。

## 18. 风险与缓解

| 风险 | 说明 | 缓解 |
|---|---|---|
| 跨讲重复 | 同一概念在第 3 讲与第 9 讲各出现一次 | **不合并**，见 §20 决策记录；仅以 `info` 提示，由作者决定是否加交叉引用 |
| 结构先于内容 | 章节结构通常在通读内容后才能确定 | 支持两遍流程：先生成平铺文档，人工调整 outline，再渲染成书 |
| 对齐质量 | 无锚点时仅能依赖词面动态规划匹配 | 仅要求确认低置信度段落，并保留人工修正层 |
| 框架与内容混淆 | 仓库中混入真实课程素材与个人笔记 | `inputs/` 与 `.study/` 不纳入版本控制，测试素材使用公开授权内容 |
| 编号漂移 | 插入内容导致全书引用错位 | 身份使用 slug，编号于渲染时计算 |
| 自查自证 | 同一模型携带写作上下文审查自身产物 | L3 强制更换模型或上下文，仅提供成品与证据 |
| 审查污染内容 | 审查结果回写知识点，导致不可复现与来源混乱 | 审查仅产 findings，应用需人工确认并记录来源 |
| 审查成本 | 整学期逐讲执行 L2 与 L3 可能超过生成成本 | 仅审查公式、数值、synthesized 及标记为疑问的知识点，其余抽样 |
| 表述空泛 | 为规避来源指称限制而将内容改写为无依据的概括 | 持续监测 `unsupported` 占比；必要时标记为 synthesized 而非改写为空话 |

## 20. 决策记录

记录被否决或被修正的设计，以及理由。看这一节能知道「什么不做，为什么不做」，避免后来者重新提出同一个想法。

### D0 库保持无模型，产品层负责调用

**背景**：最初把「命令行不调用模型」当成整个项目的原则，结果产品层缺失——用户必须
先跑 Harness、再让 agent 去填缺口，工具本身什么也没生成。

**决定**：把边界下移一层。

- `study` 命令行仍是**库**：不联网、不调模型、可离线跑完确定性部分。保证可复现与可测试。
- 新增服务层（`study serve`）：网页 + 对话 + 自动填缺口 + 渲染成品。它调用模型，
  但写入的是同一套文件（缺口、知识点、outline）。

**理由**：可复现的单位应该是「库的行为」，不是「用户的使用方式」。服务层把模型输出落盘，
因此同一份答案仍然产出同一本书；而用户不必知道缺口协议的存在。

### D1 不做跨讲知识点合并

**背景**：同一概念在不同讲次重复出现，早期设计把它列为「整学期文档最常见的缺陷」，计划生成候选合并清单。

**决定**：不合并。只以 `info` 级提示列出重名知识点，由作者决定是否加交叉引用。

**理由**：

1. 教学重复本身是有意义的。同一概念在不同讲次的语境不同，老师第二次讲时强调的往往不是第一次的内容。合并会把两处陈述揉成一个，丢掉这层信息。
2. 跨讲合并是不可逆的结构操作。合并后 `id`、证据、审查记录都要迁移，出错代价远高于「书里同一概念出现两次」。
3. 示例主体的实际体验：跟着课学的人看到重复会觉得是复习，不会觉得是冗余；真正会困惑的是「这两处说的不一致」——那是**矛盾**问题，由 L3 审查覆盖，不靠合并解决。

**替代方案**：`cross_lecture_repeat` 检查，输出 `info` 级 findings，列出重名知识点及其所在讲次。作者可据此在 unit 的 `see_also` 中加交叉引用，或什么都不做。

**代价**：书会变长；同一概念的两处表述若不一致，需要 L3 审查才能发现，而不一致本身不会因为合并而消失。
