# 素材摄取

> 状态：设计稿 v0.1
> 依赖：[architecture.md](architecture.md) §6、§7、§8
> 本文件定义各格式适配器的接口、块 id 的稳定性规则、图片降级流程与错误处理。

---

## 1. 目标与边界

摄取阶段把原始素材转换为中间表示（IR），**不调用任何模型**。因此该阶段的输出必须满足：

| 要求 | 判定 |
|---|---|
| 确定性 | 同一文件、同一版本，输出逐字节一致 |
| 只读 | 不修改 `inputs/` 下的任何文件 |
| 局部失败 | 单个文件失败不影响整批；失败详情写入 `errors.jsonl` |
| 可缓存 | 以输入文件 sha256 分片，命中则跳过 |

---

## 2. 适配器接口

```python
class Adapter:
    name: str                                  # pptx / pdf / docx / text / notes / media
    accepts: tuple[str, ...]                   # 扩展名
    def probe(self, path: Path) -> Probe       # 不解码内容的能力探测，须在 100ms 内返回
    def ingest(self, path: Path, cfg: Config) -> IngestResult
```

```python
@dataclass
class IngestResult:
    blocks: list[Block]        # 见 architecture.md §6
    assets: list[Asset]        # 导出的图片、帧
    warnings: list[Warning]    # 不阻塞的问题
    capabilities: dict         # 供 probe 阶段汇总
```

### 2.1 约定

- 块按文档自然顺序产出，**不得重排**。标题、正文、图片的相对顺序是后续分节与对齐的信息来源。
- 每个块必须携带 `loc`，且 `loc` 在该文件内唯一。同一幻灯片的多张图片通过 `shape` 区分。
- 文本一律做 Unicode NFC 归一化；不做全角半角转换、不做繁简转换、不做标点替换——任何规范化都会降低与录音转写的词面重合度。
- 空文本块不得输出。占位符（如仅有空格的文本框）跳过并计入 `warnings`。

## 3. 块 id 与稳定性

```
block_id = <src_key>-<loc_slug>
```

| 素材 | `src_key` | `loc_slug` 例 |
|---|---|---|
| `lecture-06.pptx` | `s06`（取文件名中的讲次号，无则取文件名哈希前 6 位） | `012-3`（slide 12，第 3 个块） |
| `chapter.pdf` | `pdf-a1b2c3` | `p037-2` |
| `notes.docx` | `docx-4f5e6d` | `para214` |
| `rec-06.m4a` | `rec06` | `0088`（第 88 个转写片段） |
| `my-notes.yaml` | `nt` | `0007`（条目序号） |

规则：

- `loc_slug` **必须由位置派生**，不得使用全局自增计数器。后者在同一文件中插入内容时会导致后续全部 id 漂移。
- 素材本身被修改时 id 可能变化，此时知识点通过 `evidence` 重新绑定，不要求 id 稳定。
- 转写片段的 `loc_slug` 按时间顺序编号；重新转写会产生新 id，因此转写结果与音频文件一同缓存。

## 4. 演示文稿（pptx）

### 4.1 遍历

1. 按幻灯片顺序遍历，跳过 `hidden` 幻灯片但登记 `warnings`。
2. 幻灯片内按形状树深度优先遍历，组合形状（group）递归展开。
3. 标题占位符优先输出为 `title` 块（`level` 取大纲层级），其余形状按 z-order 输出。

### 4.1.1 图形标签的识别

示意图（组织结构图、树形图、流程图）的节点文字是独立文本框，抽取后会变成大量 `A`、`B`、`C`、`T1` 这类极短条目，直接进入正文会把知识点淹没。

判定规则（确定性，不需要模型）：

- 清洗后长度 ≤ 4，且
- 匹配 `^[A-Za-z]?\d{0,3}$`、`^[A-Za-z]{1,2}\d{0,2}$` 或仅由标点与空白构成

判定为标签的文本不进入正文，按幻灯片聚合。同一知识点内累计 ≥ 3 个标签时，输出一行「图示标注：A、B、C…」；少于 3 个则丢弃。

该规则在 `knowledge` 阶段执行（需要按知识点聚合），因此 IR 层保留原始块，不提前丢弃。

### 4.2 内容抽取

| 内容 | 处理 |
|---|---|
| 普通文本框 | `bullet`；段落层级映射为 `level` |
| 自动编号列表 | 保留 `bullet`，序号信息写入 `marker` 字段 |
| 表格 | `table`，合并单元格按左上角取值并在 `merged` 中记录跨度 |
| 图表（chart） | 抽取底层数据为 `table`；渲染截图作为 `image` 资产 |
| SmartArt | 抽取节点文字为 `bullet`；结构关系记为 `warnings`，不尝试还原图形 |
| 公式（OMML） | 线性化为 LaTeX，输出 `formula`；转换失败则降级为 `image` 并登记 L2 缺口 |
| 图片 | 导出资产，见 §8 |
| 备注页 | `speaker_notes` 字段附加在其所属幻灯片的最后一个块上；含时间码时额外解析 |

### 4.3 公式线性化

1. 首选 OMML → LaTeX 的确定性转换，要求可逆（`formula_roundtrip` 抽样验证）。
2. 不支持的结构（矩阵嵌套、分段函数）降级为 `image`，并登记 `image_semantics` 缺口。
3. 禁止用模型识别公式图像作为默认路径——准确率显著低于 OMML 转换。

### 4.4 备注页

备注页常包含讲解要点，是 C 档（无录音）最重要的补充信息源。

- 附加到同一幻灯片的最后一个块：`speaker_notes: {text, timecodes}`
- `timecodes` 通过正则识别形如 `00:13:40`、`13:40`、`@13m40s` 的时间标记，命中则产出对齐锚点，见 [alignment.md](alignment.md) §3。

## 5. PDF

### 5.1 类型判定

按页采样，满足任一条件判为扫描件：

- 单页提取字符数中位数 < 50
- 页面面积内图片覆盖率 > 80% 且文字层为空

扫描件路径：

1. 若有 OCR 引擎可用，逐页 OCR 输出 `bullet`，`loc.bbox` 记录词框
2. 若无 OCR 引擎，整份文件登记 `ocr_unavailable` 警告并跳过，不阻塞其他文件
3. 图表页即使有文字层，也导出为资产并登记 L2 缺口

### 5.2 版式处理

| 问题 | 处理 |
|---|---|
| 多栏排版 | 按 x 坐标聚类分栏，按栏内 y 排序后拼接，避免串行 |
| 页眉页脚 | 检测跨页重复文本（出现在 ≥ 50% 页面且位于上下 10% 区域），剔除并登记 |
| 脚注 | 位于页面底部且字号小于正文时，保留为独立块 `type: bullet` 并标记 `role: footnote` |
| 目录页 | 识别后跳过，登记 `warnings` |
| 公式 | 文本层中的公式多为碎片，转为 `formula` 的可靠度低，默认保留原文字并登记审查提示 |

## 6. Word（docx）

1. 按段落顺序遍历，样式名映射到 `title` 的 `level`（Heading 1 → 1，依此类推）。
2. 表格、图片、公式的处理同 pptx。
3. 批注与修订：默认忽略；`cfg.docx_comments: true` 时作为 `note` 块输出，`kind: comment`，不参与对齐。
4. 目录域、页码、页眉页脚跳过。

---

## 7. 纯文本与 Markdown

- `.txt`：按空行分段；识别行首编号与缩进，产出 `bullet` 与 `level`
- `.md`：保留标题层级与代码块（`code` 含 `lang`），列表转 `bullet`，图片引用转 `image` 资产并复制至 `.study/assets/`

`math-basis-for-AI` 这类自研提取脚本的输出可直接作为 `txt` 输入接入，无需改造成适配器。

## 8. 图片降级流程

见 architecture.md §7。实现要点：

```
image 块建立
  ├─ 区域内有文字 → L1: OCR
  │     └─ OCR 结果纳入块文本，loc 记录 bbox
  ├─ L1 之后语义仍不完整 → 登记 L2 缺口（gaps/*.json）
  └─ 无文字且无语义需求 → 仅保留资产与 caption
```

### 8.1 "语义是否完整"的判定

按图片的用途分类，只有以下情况登记 L2：

| 图片类型 | 判定方式 | 是否需 L2 |
|---|---|---|
| 纯文字截图 | L1 文字覆盖率 > 90% | 否 |
| 表格截图 | L1 后能还原行列结构 | 否 |
| 流程图 / 状态图 | L1 得节点名但无法得边方向 | 是（问边集合） |
| 结构图 / 示意图 | L1 得标签但无法得包含关系 | 是（问层级关系） |
| 曲线图 / 统计图 | L1 得轴标签但无法得趋势 | 是（问关键点与趋势） |
| 装饰性图片 | L1 无文字且与正文主题无关 | 否 |

### 8.2 缺口问题模板

L2 缺口必须是可判定的具体问题，并给出回答格式。禁止「描述这张图」。

```json
{
  "kind": "image_semantics",
  "asset": "assets/3f2a....png",
  "question": "图中各节点之间的有向边集合是什么？",
  "answer_format": "[[源节点, 目标节点], ...]",
  "context": {"ocr_text": ["A", "B", "C"], "missing": "边集合"}
}
```

答案写回 IR 的 `semantics` 字段，并标记 `semantics_by`（来源）与 `confidence`。

### 8.3 资产去重

以内容 sha256 命名（`assets/<hash8>.<ext>`）。同一图片在多个讲次出现时只有一份资产，`image` 块的 `asset` 指向它。

摄取阶段产出的图一律标记 `provenance: extracted`。重画图与新增图不经过本阶段，由 `study figure add` 或 `figure_request` 缺口产生，见 [rendering.md](rendering.md) §9。

### 8.4 何时该重画而不是照搬

照搬原始截图在两种情况下会降低文档质量，此时应登记 `figure_request` 而非直接引用像素：

| 情况 | 处理 |
|---|---|
| 原图是位图且含关键文字（缩放后模糊） | 重画为 mermaid / svg，文字重新排版 |
| 原图信息残缺（被动画、被遮挡、只是某一帧） | 重画，并以 `evidence` 指向原位置 |
| 素材里根本没有能说明该概念的图 | 新增（`synthesized`），`evidence` 指向所解释的知识点 |
| 原图清晰、信息完整 | 照搬（`extracted`），不要重画 |

判断依据是「文字是否可读、结构是否完整」，不是「图是否好看」。重画有成本，也会引入新的错误来源，因此只在照搬会丢信息时使用。

## 9. 音频

### 9.1 转写流程

1. `ffmpeg` 转 16kHz 单声道 wav（消除采样率差异导致的缓存失效）
2. 语音活动检测（VAD）切分，丢弃长静音
3. 转写，要求词级时间戳；引擎支持时启用中英混合识别
4. 句子切分后产出 `speech` 块，每段不超过 30 秒或一个完整句

### 9.2 片段规则

| 情况 | 处理 |
|---|---|
| 句子跨越 30 秒 | 按最近的停顿切分 |
| 识别置信度低 | 保留但标记 `low_conf: true`，参与对齐时降低权重 |
| 明显识别错误（如专有名词） | 不自动修正，交给 L2 审查；保留原始文本 |
| 说话人切换 | v1 不做说话人分离，仅在 `warnings` 提示 |

转写结果与音频文件哈希一同缓存，避免重复转写。音频的 `probe` 只读取容器元信息（时长、采样率、声道），不解码。

## 10. 学生手记

`inputs/*.yaml`，见 architecture.md §8。摄取阶段职责：

1. 按 [hand notes schema] 校验（`at`、`text`、`kind` 为必填）
2. `at.slide` 存在时校验该幻灯片确实存在，不存在则报 `major` 并保留为全局笔记
3. `at.unit` 存在时校验知识点尚未生成（手记先于知识点时允许，标 `pending`）
4. 产出 `note` 块，`kind` 原样保留

手记的块 id 按条目序号，不按内容哈希——手记条目会持续增补，内容哈希在增补时不稳定。

## 11. 错误处理

```jsonl
{"file": "lecture-09.pptx", "stage": "pptx/omml", "severity": "warning", "msg": "3 个公式降级为图片", "slide": 14}
{"file": "scan.pdf",     "stage": "pdf/ocr",  "severity": "error",   "msg": "无可用 OCR 引擎，跳过", "page": 1}
```

| 严重度 | 含义 | 流程影响 |
|---|---|---|
| `warning` | 内容部分降级 | 继续，计入报告 |
| `error` | 该文件失败 | 跳过该文件，其余继续；若该文件为某讲唯一素材则升级为 `blocker` |
| `blocker` | 无法继续 | 终止并给出修复建议 |

禁止静默降级。任何降级都必须同时产出 warning 与对应的缺口或审查提示。

## 12. 性能约束

以一份 50 页演示文稿为基准：

| 阶段 | 约束 |
|---|---|
| probe | < 100ms |
| pptx 摄取 | < 5s |
| 图片 L1（OCR） | < 500ms/张，可并行 |
| 音频转写 | 不设上限，须显示进度并支持中断续跑 |

摄取阶段整体允许并行，但输出顺序必须确定，不得因并行而改变块顺序。

## 13. 测试要求

每个适配器至少三个 fixture：

| fixture | 用于 |
|---|---|
| 正常样本 | 断言块数量、类型分布、loc 唯一性、id 稳定 |
| 畸形样本 | 空文件、损坏压缩包、超长单行、含嵌套组合形状的幻灯片 |
| 边界样本 | 0 文本幻灯片、纯图片 PDF、含 OMML 不支持结构的公式、中英混排转写 |

断言方式：输出 IR 的规范化 JSON 与期望文件逐字节比对。新增适配器或改动抽取逻辑必须同时更新期望文件，并在提交信息中说明差异原因。
