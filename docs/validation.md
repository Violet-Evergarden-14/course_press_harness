# 实测记录

> 设计文档写得再好，也只有真实素材能证明它站得住。本文件记录每次实测的输入、结果与由此发现的问题，作为回归依据。

---

## 1. 单讲课件（第 06 章 树和二叉树）

| 项 | 值 |
|---|---|
| 输入 | 1 份 PPTX，114 张幻灯片 |
| 产出 | 1682 块 → 17 个知识点 → 4 节 → 35 KB 文档 |
| 结构 | 6.1 / 6.2 / 6.3 / 6.4，与课件编号完全一致 |
| 门禁 | 1 major（机器 id）、1 minor（2 页未覆盖） |

发现并修正：

1. 分节靠 `sqrt(n)` 猜测 → 改为读课件自带编号层级的 §3.0 规则
2. 单级编号（`2. 链式存储结构`）被当结构 → 只认含小数点的编号
3. 树形图节点标签（A/B/C）淹没正文 → §4.1.1 标签识别

## 2. 三章连续（第 01–03 章）

| 项 | 值 |
|---|---|
| 输入 | 3 份 PPTX，245 张幻灯片 |
| 产出 | 2881 块 → 14 个知识点 → 文档 |

**结论：这批课件没有可用的结构信号。** 标题不是占位符，也不是编号小标题，而是字号较大的普通文本框；页眉「第1章 绪论」在多张幻灯片上重复。第一版结果只有 **3 个知识点**（每份课件一个），因为整份课件没有任何一处能被识别为分节边界。

由此补上 §4.1.0 标题推断（字号 ≥24pt、CJK 优先、页眉排除、列表项排除）与 §3.0.1 按标题连续段聚类。修正后：

| 项 | 修正前 | 修正后 |
|---|---|---|
| 知识点 | 3 | 14 |
| 章节 | 1.1（一大节） | 1.1–1.4 / 2.1–2.3 / 3.1–3.2 |
| 识别到标题的幻灯片 | 4 / 56（ch1） | 52 / 56 |

同时发现两处过紧的阈值：

- 页眉判据最初取「出现 ≥25%」，把只在两页上重复的**小节标题**也误判成页眉。改为「≥50% 且 ≥3 页」——小节标题的重复是正常的，页眉的重复是压倒性的。
- 标题回退最初只取「最靠上的短行」，在代码页上取到 `{`、`p`、`Q.rear`。加上 CJK 优先与标识符排除后才可用。

## 3. 追加讲次（在第 1–3 章后加入第 04 章）

| 项 | 值 |
|---|---|
| 操作 | 补一份 PPTX 与一条 lecture 配置，重跑 `study auto` |
| 结果 | 20 个知识点，第 4 讲追加在末尾 |
| 关键断言 | **前 3 讲正文逐字节一致**（`_ws3` 实测，diff 为空） |

这验证了设计里最核心的一条承诺：新增讲次不会重写既有内容。
